# 开发阿雷 · 个人工作站

中文个人博客，包含写作、项目、说说、AI 手记、投资研究、网站收藏与生活记录。前台保留现有视觉和交互，后台位于 `/admin`，通过表单管理内容。

本项目当前按**本地运行**维护。数据库和上传素材都存放在本机，不需要登录 Cloudflare 或 ChatGPT，不会自动发布或上传站点。

## 快速开始

需要 Node.js **22.13 或以上**和 npm。以下命令均在项目根目录执行：

```powershell
npm ci
npm run db:migrate
npm run admin:password
npm run dev
```

打开终端打印的本地地址，默认是 [http://localhost:3000](http://localhost:3000)。后台为 [http://localhost:3000/admin](http://localhost:3000/admin)。如开发服务器使用其他端口，后台也使用同一端口。

管理员密码由 `npm run admin:password` 随机生成并显示，同时保存在根目录 `.dev.vars` 中。后台只需要密码，不需要用户名。

### 已经在运行 npm run dev

这次新增了数据库、素材存储绑定和管理员环境变量，需要**重启一次开发服务**才能完整加载。先在原终端按 `Ctrl+C`，再运行 `npm run dev`。本次实现已安装依赖、执行本地迁移并生成 `.dev.vars`；当前工作目录无需再次初始化。查看本地 `.dev.vars` 获取密码即可。

`npm run admin:password` 检测到已有密码时不会覆盖。忘记密码时执行：

```powershell
npm run admin:password -- --reset
```

随后重启开发服务；旧登录会话会失效。请勿把 `.dev.vars` 发送给别人或提交到版本库。

### 编辑、排序与发布

「页面标题与配图」和「页面固定文案」采用左侧页面目录、右侧编辑区，一次只展开当前页面。旅行页介绍与配图、说说页文案与封面 / 图库说明分别集中在对应页面；共用内容标为「生活栏目通用」「全站播放器」「全站导航」。

这两个栏目内切换页面会保留修改，左侧以「未保存」标记有改动的页面。「保存栏目」统一保存该栏目所有页面的修改；右侧「查看页面」可打开当前页面。

1. 登录后台，选择左侧栏目，再选择具体记录。
2. 支持新增、删除和上移 / 下移。项目图片、正文段落等嵌套列表也能独立编辑与排序。
3. 新增记录默认为草稿。填写必填内容，勾选「发布到前台」，点击「保存栏目」。保存以整个栏目为单位。
4. 点击「查看前台」，或刷新已经打开的前台页面查看结果。已有页面不会自动轮询更新。

取消「发布到前台」后保存，可以下架记录。草稿在服务端过滤，不会出现在前台 HTML、列表或公开文章详情中。站点配置和页面文案保存后直接生效。

离开有未保存修改的栏目时会提示。两个后台窗口同时修改同一栏目时，第二次提交会提示版本冲突；先导出当前编辑，再重新载入最新内容进行合并。

写作以表格作为入口，支持标题 / 摘要搜索、分类（含子分类）和发布状态筛选，以及编辑、发布 / 转草稿、排序、删除。进入编辑后返回表格会保留修改，发布与删除统一在“保存栏目”后生效。写作采用专用表单：发布状态单选「草稿 / 发布到前台」，发布日期使用浮层中文日历选择，不挤占表单空间；选择后自动关闭，也可按 Esc 或点击外部关闭（仅展示日期，不是定时发布）。正文使用 `@uiw/react-md-editor`，显式保留有序、无序、嵌套和任务列表样式，提供工具栏和内置编辑、分屏、预览模式，支持 Markdown 标题、列表、引用、链接、图片、代码和表格。二级标题生成文章目录。原始 HTML 不执行。`slug` 决定 `/writing/slug` 地址；修改后旧地址不再有效。

示例内容不代表真实经历、作品或投资结论。原来的共用示例文章已迁移为可单独编辑的各篇正文。替换为真实内容后，可以在页面固定文案中同步修改示例说明。

说说支持多个话题，前台左对齐显示且只添加一个 `#`；输入话题时可带 `#`，系统会统一处理。发布日期按北京时间保存到秒，前后台列表均按该日期从新到旧排列。新增说说默认保存为草稿，勾选“发布到前台”并保存后才公开。图片位于文字之后，可上传或根据正文和话题使用已配置的图片模型生成，生成后点击“保存栏目”。说说列表与封面标签切换会保留草稿，保存按钮只保存当前标签。旧单话题自动转换为话题列表，旧示例点赞与回复不再展示。

说说评论功能已移除，前后台均不提供评论入口，原评论接口也已删除。本地评论表已清空；保留表结构以兼容现有迁移记录，应用不再读取或写入评论。

### 文章分类与 AI 封面

写作页面的“文章分类”标签采用层级目录与编辑区，支持新增顶级 / 子分类、展开收起、调整上级和同级排序。上级选项排除自身与后代，服务端同时校验循环关系、失效上级和同级重名；不同分支可使用同名分类。旧分类自动作为顶级分类加载。先保存分类，再切换“文章管理”通过完整分类路径选择。分类改名保留关联并同步前台；仍有子分类或文章使用时不能删除，草稿也计入。父分类筛选会包含后代分类文章，前台分类导航同步按层级展示。旧文章分类会自动兼容，不需要手工迁移。

1. 在根目录 `.dev.vars` 添加 `TEAMOROUTER_KEY=你的密钥`，重启 `npm run dev`。密钥只由服务端读取，不进入浏览器或内容 JSON 备份。
2. 打开「AI 大模型设置」的“模型配置”标签。默认 Base URL 为 `https://api.teamorouter.com/v1`，文本模型为 `gpt-5.4-mini`，图片模型为 `gpt-image-2`。也可填写其他 OpenAI 兼容服务的 HTTPS Base URL 和模型；更换服务时同时替换密钥。
3. 模型选择使用统一的搜索浮层，点击即可展开全部已获取的模型，无需清空当前值。支持键盘选择和输入自定义模型名称。保存设置后，可「获取模型列表」或「测试文本模型」。文本测试与图片生成会实际调用服务并使用账户额度。
4. 在“写作配置”标签配置封面风格和提示词。切换标签保留未保存输入，两者统一保存。`{{title}}`、`{{excerpt}}` 分别替换文章标题和摘要，必须保留；`{{style}}` 替换上方风格。
5. 编辑文章的「文章封面」，单选「上传文件」或「AI 生成」。AI 模式可点击生成，也可直接保存栏目：缺少封面或标题 / 摘要变化时会先生成再保存。手动重生成可应用新的风格设置。

封面调用 `/images/generations`，支持 Base64 或 HTTPS 图片地址，下载后保存到本地素材库。生成最长等待约 5 分钟，不自动重试；失败保留原封面和未保存修改。若栏目保存失败，已生成的图片仍留在素材库，当前编辑保留生成结果，避免再次付费生成。保存以整个写作栏目为单位，会处理该栏目中所有待生成的 AI 封面。

本机配置 `HTTPS_PROXY` / `HTTP_PROXY` 时，开发与构建预览会自动启动仅监听本机、使用临时令牌的 AI 网络适配服务，无需另启进程。没有代理环境变量时直接请求中转站。AI 设置不发送到前台；调用 AI 时文章标题、摘要和风格会发送到你配置的中转站。接口说明：[Teamorouter 开发文档](https://teamorouter.com/zh/docs/api-integration)。

### 项目管理

项目栏目包含“项目列表 / 项目状态 / 项目分类”三个标签。列表支持搜索、按状态和分类筛选、编辑、发布 / 转草稿、排序及删除；返回表格或切换标签保留输入。三个标签的数据统一点击“保存栏目”原子保存。

项目状态、项目分类为独立的扁平选项，可新增、改名、删除。项目表单通过下拉框选择；改名保留关联，被项目（含草稿）使用的选项不能直接删除。请先调整关联项目再删除选项。

项目表单保留名称、副标题、年份、工作范围、摘要、图片、标签和发布状态，新增“项目说明” Markdown 编辑器，支持分屏与预览。前台直接渲染项目说明，原始 HTML 不执行。编号、起点问题、设计选择、过程步骤、下一步已从前后台项目界面移除。

项目标签独立展示，输入后按 Enter 或点击“添加标签”，可逐个移除。项目图片使用无外框的图片编辑区，每张可选“上传文件 / AI 生成”，第一张作为封面；支持添加、移除和排序。上传支持 PNG、JPEG、WebP、GIF（最大 20 MB），也可填写已有素材地址。

AI 设置新增“项目配置”：图片风格与提示词支持 `{{title}}` 项目名称、`{{subtitle}}` 副标题、`{{excerpt}}` 摘要、`{{style}}` 风格，前三个占位符必须保留。使用“模型配置”中的图片模型与中转站密钥。项目编辑时可单独生成；保存时会为尚未生成或名称 / 副标题 / 摘要已改变的 AI 图片先生成再保存。多张 AI 图片分别调用服务；生成失败保留原图和编辑，不自动重试。改风格后可手动重新生成。

旧项目数组自动转为包含项目列表、状态和分类的文档，保留现有项目与选项关联；旧的栏目备份也可导入。读取兼容不会立即改写数据库，保存后使用新结构。被移除的字段不会自动塞入项目说明，项目说明初始为空，可自行补充；如需保留旧字段的原文，请在保存前保留原始备份。

前台写作分类显示后台的全部分类（含 0 篇文章的分类），按真实父子关系嵌套展示；父分类数量与筛选包含后代文章。小屏也提供分类入口。

### 素材上传

图片 / 音频字段旁可直接「上传替换」，也可在素材库上传后复制地址。支持 PNG、JPEG、WebP、GIF、MP3、WAV，单文件最大 **20 MB**。后端按文件头检查格式，不接受 HTML 或 SVG 上传。

上传后需要保存对应栏目，才会更换页面使用的素材。返回地址形如 `/api/media/…`。这些素材地址公开可访问，草稿过滤不等于素材保密。已有 `public/` 素材仍可直接填写路径，例如 `/covers/writing-notes.png`；素材库列表显示后台上传或 AI 生成的文件。

删除内容记录不会删除其上传文件，避免其他页面引用失效。当前素材库提供上传、列出、查看和复制地址，不提供批量清理。

## 数据与备份

- 结构化内容：本地 D1 / SQLite，位于 `.wrangler/state/v3/d1/`。
- 上传文件：本地 R2，位于 `.wrangler/state/v3/r2/`。
- 管理员密码：`.dev.vars`。
- 默认内容：`lib/cms-defaults.ts`、`lib/page-copy.json`、`lib/article-seed.json` 及原有数据模块。

数据源是服务端数据库，**不是浏览器 localStorage**。刷新、换浏览器、重启开发服务后仍保留。尚未保存过的栏目读取代码中的默认内容；一旦保存，以数据库中的内容为准。清空列表不会重新出现默认条目。

### 内容备份

后台「导出内容备份」下载 JSON，包含所有栏目，以及当前栏目尚未保存的编辑。恢复时选择目标栏目，点击「导入此栏目」，选择备份文件、检查内容，再保存。全站恢复需要逐个栏目导入；导入不会立即覆盖服务器。

JSON 只包含内容和素材地址，**不包含评论、上传文件本身、管理员密码或登录会话**。

### 完整本地备份

停止开发 / 预览服务后，复制整个 `.wrangler/state` 目录，并单独妥善备份 `.dev.vars`。同一项目和绑定配置下，将状态目录放回相同位置即可恢复数据库与素材。不要只复制单个 SQLite 文件而遗漏 WAL 或 R2 元数据。

`.wrangler/`、`.dev.vars`、测试临时文件和构建产物均已加入 Git 忽略规则。不要删除 `.wrangler/state`，除非确实希望清空本地数据。

集成测试使用独立 checkout、独立 D1 / R2 状态和 `3107` 端口。不会写入日常使用的 `.wrangler/state`，也不会停止已运行的开发服务。需要先生成 `.dev.vars`，并确保 `3107` 未被其他程序占用。

测试覆盖：管理员登录、未登录拒绝、跨站写入拒绝、所有栏目保存、分类增删改与引用保护、AI 设置隔离和校验（不发送付费请求）、草稿隐藏、文章发布与 Markdown、重复标识与非法网址、版本冲突、首页联动、素材字节与范围请求、重启后的持久化、空栏目路由、退出和登录限流。日志保留在 `.wrangler/cms-test-*/server.log`，测试 checkout 位于 `work/cms-test-app-*`。

类型检查与构建之外，完整 `npm run lint` 仍包含项目原有 UI 组件及主题初始化的静态检查问题；本次新增后台代码单独检查通过。接口测试不等于浏览器视觉或交互验收，本次未执行浏览器自动点击 / 截图测试。

## 项目结构

```text
app/                    前台页面、/admin 与服务端 API
components/             前台组件、后台表单、内容 Context
lib/cms-defaults.ts     管理栏目与默认数据
lib/cms-server.ts       D1 读写与公开内容读取
lib/cms-validation.ts   字段校验、草稿过滤
lib/admin-auth.ts       登录会话与请求保护
db/schema.ts           数据表定义
drizzle/               已生成的 SQL 迁移
scripts/               密码初始化与集成测试
public/                项目自带静态素材
wrangler.local.json    本地迁移绑定配置
vite.config.ts         Vinext / Cloudflare 本地运行配置
```

技术栈：React 19、TypeScript、Vinext / Vite、Cloudflare 本地 D1 与 R2、Drizzle 迁移、React Markdown。使用单管理员密码、8 小时 HttpOnly / SameSite 会话、服务端权限检查和持久化登录限流；没有多用户、角色分配或找回密码邮件流程。

## 常见问题

- **看到「请先配置密码」**：运行 `npm run admin:password`，随后重启开发服务。
- **提示数据库表不存在**：在项目根目录执行 `npm run db:migrate`，然后重启。不要从其他目录启动服务，否则可能读取不同的本地状态。
- **更新代码后旧开发进程报错**：本次增加了运行时绑定并安装依赖，需要完整重启一次，单纯刷新浏览器不能代替重启。
- **保存后看不到内容**：确认已保存栏目、条目已发布、前台筛选条件没有隐藏它，并刷新前台。
- **书单删除了书籍后仍保留 ID**：前台会忽略不存在或未发布的书籍；可在书单中手动移除对应 ID。
- **忘记密码**：运行 `npm run admin:password -- --reset` 后重启。
- **本地请求受代理影响**：检查代理的 localhost 排除设置；命令行可使用 `curl.exe --noproxy "*" http://localhost:3000/`。
- **准备部署到服务器**：本 README 只覆盖本地使用；需要另外配置生产存储、密钥和 HTTPS。本项目不会自动执行部署。
